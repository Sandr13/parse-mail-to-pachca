# parse-mail-to-pachca
Функция для автоматической обработки входящих email-сообщений и пересылки уведомлений в Pachca

## Функция:
- читает последние письма из почты
- фильтрует только новые (за заданный период)
- извлекает данные (отправитель, получатель, тема, тело)
- определяет пользователя в Pachca по email
- отправляет уведомление в Pachca

## Основные возможности
1. Работа через IMAP (OAuth2, без пароля)
2. Фильтрация писем по времени (последние N минут)
3. Кеширование пользователей (уменьшение нагрузки на API)
4. Поддержка специальных писем (devnull)
5. Обработка уведомлений из Яндекс.Трекера
6. Защита от дублей внутри одного запуска
7. Гибкая конфигурация через переменные окружения

## Архитектура
Email (IMAP) → Фильтрация (по времени) → Парсинг (subject, from, to, body) → Логика маршрутизации → Pachca API

## Переменные окружения

### Pachca
PACHCA_API_TOKEN=your_pachca_token

### IMAP (Яндекс)
IMAP_SERVER=imap.yandex.ru
IMAP_PORT=993
YANDEX_MAIL_LOGIN=your_email@yandex.ru
YANDEX_MAIL_TOKEN=your_oauth_token

### Настройки обработки
EMAIL_FETCH_LIMIT=50
SINCE_MINUTES=5

### Таймауты
SOCKET_TIMEOUT=10
REQUESTS_TIMEOUT=15

### Администратор (fallback)
ADMIN_PACHCA_ID=123

### Помечать письма как прочитанные
MARK_PROCESSED_AS_SEEN=false

## Запуск
Функция запускается через handler(event, context)

Можно использовать:
cron / scheduler

## Логика обработки
1. Обычные письма
Определяется получатель (To)
Ищется пользователь в Pachca
Отправляется уведомление

Если в теме есть ключ задачи (ABC-123):
→ добавляется ссылка на Tracker

2. Специальные письма (devnull@yandex.ru)
Из тела извлекается email
Чистится HTML
Сообщение отправляется найденному пользователю

Если пользователь не найден:
→ сообщение отправляется администратору

3. Исключения

Игнорируется адрес:

send.pachca@bnovo.ru

## Оптимизации
Сначала загружаются только заголовки (быстро)
Тело загружается только при необходимости
Используется кеш пользователей
Ограничение на количество писем (limit)

## Ограничения
IMAP поиск работает только по дате (без времени)
Возможны дубли между запусками
Нет персистентного хранения UID (например Redis)
